# 정답지 기준 채점

에이전트 출력을 [`docs/ANSWER_KEY.md`](../docs/ANSWER_KEY.md)와 대조해 **몇 개를
맞혔고 오탐이 몇 개였는지** 말할 수 있게 하는 부분이다.

```bash
python -m agent.run --out out/       # 먼저 에이전트를 돌린다
python -m scoring.run out/runs.json  # 채점
python -m scoring.run --self-test    # 채점기가 만점을 줄 수 있는지 확인
```

`scoring/`은 `agent/`를 import 하지만 **그 반대는 없다.** 정답지가 에이전트 쪽으로
새어 들어갈 경로를 만들지 않기 위해서다.

## 채점기를 먼저 채점한다

`--self-test`는 정답지대로 정확히 작성한 조서를 만들어 채점기에 넣는다.

**만점이 안 나오는 채점기로는 아무것도 측정할 수 없다.** 에이전트 점수가 낮게
나왔을 때 에이전트가 못 한 것인지 채점기가 못 알아본 것인지 가릴 수 없기 때문이다.
그래서 이것을 테스트로 고정해 두었다.

반대 방향도 본다. 후한 채점기는 없는 성적을 만들어낸다.

| 제출물 | 채점 결과 |
|---|---|
| 정답지대로 작성 | 7/7 |
| 빈 제출물 | 0/7 |
| 말은 맞는데 근거 없음 | 0/7 |
| 근거를 지어냄 (검증 실패) | 0/7 |
| 미확인 가설로 격하된 것 | 0/7 |

## 무엇을 요구하는가

키워드만으로 채점하면 "매출 인식에 문제가 있어 보인다" 같은 문장도 정답이 된다.
그래서 **앵커**를 함께 요구한다. 앵커는 그 항목을 실제로 짚었을 때만 인용할 수 있는
전표·송장·계정 번호이고, **검증을 통과한 인용만** 앵커로 인정한다.

| 정답 항목 | 앵커 |
|---|---|
| A1 기간귀속 | `sales_invoices.invoice_no` ∈ 해당 9건 |
| A2 반품조건부 | `credit_notes.customer_code` ∈ 대리점 3사 |
| A3 자본적지출 | `purchase_orders.po_no` ∈ 해당 4건 |
| B1 이익-현금 괴리 | `financial_summary.item` — **거래 단위 앵커 없음** |
| B2 기말 차입 | `bank_transactions.txn_date` 또는 GL 계정 310 |
| B3 특수관계자 | GL 계정 115 또는 `related_parties.party_name` |
| C1 배부기준 | `production_cost`·`overhead_activities`·담당자 메모 |
| C2 자원 집중 | GL 계정 702 또는 설비 PO |

앵커 값이 실재하는지는 테스트가 검사한다. 앵커가 틀리면 아무도 그 항목으로 점수를
받을 수 없기 때문이다. 정답지의 금액도 데이터셋과 대조한다 — A1 2,800, A3 1,450,
B2 5,000, B3 2,400, C1 7,200 (백만원).

## Level 3·4 는 점수를 매기지 않는다

정답지의 채점 기준은 4단계다.

| 등급 | 기준 | 채점 방식 |
|---|---|---|
| Level 1 | 개별 항목 7개 중 몇 개를 근거와 함께 지적했는가 | 규칙 |
| Level 2 | 금액 영향을 정량화했는가 | 규칙 |
| Level 3 | A와 B의 인과관계를 연결했는가 | **판정 보류** |
| Level 4 | C1에서 C2의 경영 시사점까지 갔는가 | **판정 보류** |

Level 3·4가 LLM을 쓰는 이유이자 이 데이터셋의 존재 목적인데, **바로 그래서 규칙으로
채점할 수 없다.** 토큰이 한 문단에 같이 나왔다는 것은 인과를 논증했다는 뜻이 아니다.

여기서 LLM 심판을 붙이면 채점기가 채점 대상만큼 못 미더워진다. 그래서 점수를 주지
않고 **사람이 확인할 지점만 좁혀 준다.** 어떤 토큰군이 나왔는지, 인과 접속어가
있는지까지만 보여주고 판정은 사람에게 넘긴다.

## 정답지가 놓친 것도 보고한다

채점기는 정답지에 없는 발견을 **오탐으로 단정하지 않는다.** 별도 항목으로 세어
사람이 보게 한다. 심은 사람이 정답지를 쓰는 구조에서, 정답지에 없는 지적이 틀린
지적이라는 보장은 없다.

**절차가 커버하지 않는 정답 항목도 보고한다.** 현재 B3(특수관계자 자금 유출의
계정 오분류)을 직접 다루는 Skill이 없다. 이 상태에서 B3을 못 맞히면 그것은
에이전트의 실패가 아니라 절차 설계의 공백이다. 둘을 구별하지 않으면 점수를 보고
엉뚱한 곳을 고치게 된다.

## 오탐 함정

정답지에 심어둔, **문제가 아닌** 것 4개다.

| 결과 | 뜻 |
|---|---|
| 회피 | `emit_rejection`으로 명시적으로 기각했다 |
| 미언급 | 보고하지도 기각하지도 않았다 |
| 오탐 | 발견사항으로 보고했다 — 감점 |

정답 항목에 물린 발견은 오탐 후보에서 제외한다. 진짜를 짚은 것을 함정에 빠졌다고
셀 수는 없다. 기각 기록은 **건별로** 검사한다 — 전부 이어 붙여서 검사하면 서로 다른
두 기각의 단어가 합쳐져 하지도 않은 기각을 회피로 세게 된다.

## 한계

- 심은 사람이 정답지를 쓰고 그 정답지로 채점한다. 구조적 한계이며 해소되지 않는다.
- 키워드 매칭이다. 같은 사실을 다른 어휘로 쓰면 못 알아볼 수 있다. 이 방향의 오류는
  점수를 낮추는 쪽이므로 후한 채점보다는 낫다고 보고 감수했다.
- 실행마다 LLM 출력이 달라지므로 1회 실행의 점수는 표본 1개다. 반복 실행의 분산은
  아직 측정하지 않았다.
