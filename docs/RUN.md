# 실행 기록

클론하지 않고도 이 저장소가 무엇을 내는지 볼 수 있게, **실제 터미널 출력을 그대로**
붙여 둔 문서다. 아래 네 실행은 전부 **API 키 없이** 재현된다.

```
Python 3.14.6 · 외부 의존성 없음 (표준 라이브러리만) · 네트워크 불필요
```

| 실행 | 명령 | 결과 |
|---|---|---|
| 1. 전체 검증 | `python -m unittest discover tests` | 82개 통과 |
| 2. 채점기 자기 채점 | `python -m scoring.run --self-test` | Level 1 **7/7** |
| 3. 규칙 기반 대조군 | `python -m agent.baseline --out out/baseline` | 발견사항 7건 |
| 4. 대조군 채점 | `python -m scoring.run out/baseline/runs.json` | Level 1 **6/7** |
| 5. LLM 에이전트 | `python -m agent.run --out out/` | **미실행** (API 키 필요) |

정답지는 [`docs/ANSWER_KEY.md`](ANSWER_KEY.md)에 7+1개 항목과 4개 오탐 함정으로
정의되어 있고, 에이전트 쪽 코드는 이 파일을 참조하지 않는다(테스트로 고정).

## 2. 채점기 자기 채점

**만점이 안 나오는 채점기로는 아무것도 측정할 수 없다.** 에이전트 점수가 낮게 나왔을
때 에이전트가 못 한 것인지 채점기가 못 알아본 것인지 가릴 수 없기 때문이다. 그래서
정답지대로 정확히 작성한 조서를 넣어 만점을 확인한다.

```
$ python -m scoring.run --self-test

Level 1  개별 항목 탐지   7 / 7
Level 2  금액 정량화      7 / 7 (탐지된 것 중)

오탐 함정
  [회피] T1 정상 거래처의 반품 3.0%
  [회피] T2 12월 매출 스파이크 자체
  [회피] T3 월중 운영자금 차입 6건
  [회피] T4 출고일이 송장일보다 빠른 정상 건

결과: 통과 — 만점 7/7
```

반대 방향(후한 채점)도 테스트로 막아 둔다. 빈 제출물·근거 없는 발견·지어낸
근거·격하된 가설은 모두 0/7 이다. [`scoring/README.md`](../scoring/README.md) 참조.

## 3. 규칙 기반 대조군 — LLM 없이 어디까지 가는가

이 저장소는 "Level 3·4(인과 연결) 때문에 LLM 이 필요하다"고 주장한다. 주장은 측정으로
뒷받침되어야 하므로, **판단 주체를 LLM 이 아니라 임계값 표로 바꾼 대조군**을 같은
계산 결과 위에 올려 돌린다. 규칙은 7개이며 전부
[`agent/baseline.py`](../agent/baseline.py)에 있다.

## 이 실행에서 읽어야 할 것 네 가지

### ① 개별 항목 탐지(Level 1)는 대부분 결정론적 도구가 한 몫이다

규칙만으로 6/7 이 나왔다. LLM 이 개별 항목 탐지를 잘해서가 아니라, **`tools/` 가
이미 무거운 일을 끝내 놓았기 때문**이다. 인도조건별 통제이전일 판정, 활동기준 재배부,
금액 일치·방향 반대 거래쌍 매칭은 전부 코드가 한다. 남은 것은 "이 수치가 발견사항인가"
한 줄 판정이고, 그 판정은 임계값으로도 된다.

이것은 `tools/` 설계가 옳았다는 증거이면서, **Level 1 점수로 LLM 을 자랑할 수 없다는
뜻**이기도 하다.

### ② 규칙은 함정을 '기각'하지 못한다 — 그냥 언급하지 않는다

오탐 함정 4개가 전부 `미언급`이다. 대조군은 함정을 밟지 않았지만 **회피한 것도 아니다.**
임계값 아래로 조용히 걸러졌을 뿐이고, 조서에는 아무 기록도 남지 않는다.

정상 반품률 3.0% 거래처를 검토하고 기각한 것과, 임계값에 안 걸려서 애초에 보지 않은
것은 감사 조서에서 전혀 다른 일이다. 후자는 **검토했는지 안 했는지 알 수 없다.**
`emit_rejection`을 도구로 만들고 `rejection_checks`를 필수 필드로 둔 이유가 여기서
드러난다.

### ③ Level 3·4 대리지표는 빈 서술에도 만점으로 켜진다

대조군의 `narrative` 는 **빈 문자열이다.** 인과 논증이 한 줄도 없다. 그런데도
대리지표는 토큰군 2/2, 3/3 이 전부 출현했다고 표시한다 — 발견사항에 적힌 수치와
`31.8% → -8.2%` 의 화살표 때문이다.

**이것이 이 실행에서 가장 중요한 결과다.** Level 3·4 를 규칙으로 채점하지 않기로 한
결정이 옳았다는 것을, 주장이 아니라 실측으로 보여준다. 만약 토큰 출현에 점수를
붙였다면 대조군이 인과 추론 만점을 받았을 것이다. 이 상태는
[`tests/test_baseline.py`](../tests/test_baseline.py)의
`TestLevel34ProxyIsNotEvidenceOfReasoning`으로 고정해 두었다.

### ④ 못 맞힌 두 개는 성질이 다르다

| 항목 | 왜 못 맞혔는가 | 무엇의 문제인가 |
|---|---|---|
| B3 특수관계자 | 이 항목을 다루는 Skill 이 아예 없다 | **절차 설계의 공백** |
| C2 자원 집중 | 규칙은 지적했으나 채점기가 물지 못했다 | **채점기의 한계** |

C2 는 대조군이 실제로 지적했고 조서에 들어 있다. 채점기가 요구하는 앵커(판촉비 계정)와
규칙이 인용한 앵커(전표번호)가 달라 매칭에 실패했을 뿐이다. 앵커를 맞추려면 계정번호를
규칙에 직접 박아야 하는데, 그러면 규칙이 아니라 정답 복사가 된다. **이 방향의 오류는
점수를 낮추므로 후한 채점보다는 낫다고 보고 감수했다.**

둘을 구별하지 않으면 점수를 보고 엉뚱한 곳을 고치게 된다. 채점기가 이 구별을 출력에
직접 넣는 이유다.

## 5. LLM 에이전트 실행 — 아직 비어 있다

```
$ python -m agent.run --out out/
```

이 칸은 채워지지 않았다. Anthropic API 키가 필요하고, 이 저장소를 만든 환경에는 키가
없다. **키 없이 돌린 척한 `runs.json` 을 넣지 않았다.** 지어낸 근거를 코드로 격하시키는
장치를 만들어 놓고 성적표를 지어내면 그 장치의 주장이 자기모순이 된다.

키 없이 확인할 수 있는 것은 **무엇을 보낼 것인가**까지다.

```
$ python -m agent.run cutoff --dry-run
DRY RUN — API 호출 없음. 전송할 내용만 출력한다.

[도구 스키마] 4종
  - run_procedure  (필수: procedure)
  - lookup_records  (필수: dataset)
  - emit_finding  (필수: finding, risk_grade, evidence, rejection_checks,
                        follow_up, questions_for_management)
  - emit_rejection  (필수: candidate, rejection_condition, basis)

[cutoff] 수익의 기간귀속 검토   system 3,540자 / user 371자
```

LLM 실행 성적이 나오면 이 문서에 대조군과 나란히 적는다. 그때 비교해야 할 것은
Level 1 숫자가 아니라 **기각 기록의 유무와 서술의 인과 구조**다. 위 ②·③이 그 지점을
가리키고 있다.

## 재현

```bash
git clone <this repo> && cd audit-signal-agent
python -m unittest discover tests            # 82개
python -m scoring.run --self-test            # 채점기 만점 확인
python -m agent.baseline --out out/baseline  # 대조군 실행
python -m scoring.run out/baseline/runs.json # 대조군 채점
```

설치할 것이 없다. 표준 라이브러리만 쓴다.
