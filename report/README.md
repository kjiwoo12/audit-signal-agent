# 조서 렌더러

조서 JSON 을 **한 파일로 완결된 HTML 문서**로 만든다.

**→ [실제 산출물 열어보기](https://kjiwoo12.github.io/audit-signal-agent/report/baseline.html)**
(소스는 [`docs/report/baseline.html`](../docs/report/baseline.html) 에 커밋되어 있다)

```bash
python -m agent.baseline --html docs/report/baseline.html   # 대조군 조서 (API 키 불필요)
python -m agent.run --html out/report.html                  # 에이전트 조서
python -m report out/baseline/workpaper.json -o r.html      # 이미 있는 JSON 을 렌더링
```

의존성 없음. **자바스크립트도 쓰지 않는다** — 드릴다운은 `<details>` 만으로 만든다.
외부 스크립트·스타일·이미지·폰트를 하나도 참조하지 않으므로 첨부해서 보내도, 5년 뒤에
열어도 같은 문서다. 조서는 보존 대상이고, CDN 은 보존 대상이 아니다.

## 왜 별도 계층인가

조서의 **내용**은 `agent/` 가 만든다. 여기서는 그 내용을 한 글자도 바꾸지 않고
**읽는 순서만** 정한다.

렌더러가 요약하거나 보태기 시작하면 **화면에 보이는 것과 채점기가 채점한 것이
갈라진다.** 그때부터 "에이전트가 이렇게 판단했다"는 말의 근거가 없어진다. 그래서
렌더러는 계산도 판단도 하지 않는다.

## 세 층으로 나눈다

경영진과 실무자가 같은 문서를 읽지만 필요한 깊이가 다르다.

| 층 | 내용 | 누가 읽는가 |
|---|---|---|
| 1층 결론 | 몇 건, 얼마, 근거등급 분포, 기각 건수 | 여기까지만 읽는 사람 |
| 2층 요약표 | 건별 한 줄 + 위험등급 + 추정 영향금액 | 어디를 볼지 고르는 사람 |
| 3층 드릴다운 | 정량화 · 근거 · **원천 CSV 행 원문** | 믿을지 말지 판단하는 사람 |

**3층을 접어 두는 것이 핵심이다.** 펼쳐 놓으면 아무도 1층을 읽지 않고, 빼 버리면
아무도 조서를 믿지 않는다. `<details>` 가 기본 닫힘인지를 테스트가 검사한다.

## 감추지 않는다

조서에서 **빈칸은 "검토하지 않았음"과 "검토했으나 해당 없음"을 구별해 주지 못한다.**
그래서 비어 있는 항목은 공백으로 두지 않고 그 사실을 문장으로 적는다.

| 조서 상태 | 화면에 나가는 문장 |
|---|---|
| `rejected_candidates == []` | "기각 기록이 없다. 정상 판정을 **기록하지 않았다**는 뜻이다. 임계값 아래로 걸러진 항목과 검토 후 기각한 항목을 이 조서로는 구별할 수 없다" |
| `narrative == ""` | "이 엔진은 서술을 생성하지 않는다. 빈칸이 아니라 이 엔진의 설계다" |
| `rejection_checks == []` | "이 엔진은 기각 조건을 검토하지 않는다" |
| 근거등급 B | 초록이 아닌 주황 배지 + "전표는 실재하나 인용한 원문을 그 행에서 찾지 못했다" |

미확인 가설(격하된 발견)은 **요약표에 섞지 않고 별도 섹션**에 격하 사유와 함께 낸다.
같은 표에 넣으면 격하 자체가 무의미해진다. 이것도 테스트가 검사한다.

## 합계를 그대로 내놓지 않는다

추정 영향금액의 단순 합계 옆에 이 문장을 붙인다.

> **합계를 그대로 쓰지 마십시오.** 절차 간 중복을 조정하지 않은 단순 합계다. 6번
> 절차(자원배분 정합성)는 앞선 절차의 발견을 인과로 엮으므로 같은 금액이 두 번
> 집계될 수 있다. 중복 조정은 사람이 판단해야 한다.

숫자를 크게 보이게 하는 것은 쉽고, 그 숫자가 무엇의 합인지 밝히는 것은 귀찮다.
후자를 하지 않으면 조서가 아니라 홍보물이다.

## 인쇄를 전제한다

조서는 출력되고 파일철에 들어간다. `@media print` 에서 배경·테두리·링크 밑줄을 걷어내고
`<details>` 를 펼쳐진 형태로 조판한다. 화면에서 접혀 있던 근거가 종이에서 사라지면
그 조서는 근거가 없는 조서다.

## 검증

```
python -m unittest tests.test_report -v      # 16개
```

렌더러 테스트는 "예쁘게 나오는가"를 보지 않는다. 네 가지를 본다.

| 묶음 | 검증 |
|---|---|
| `TestSelfContained` | 외부 참조 0개, 태그 주입 이스케이프, **두 번 렌더하면 같은 바이트** |
| `TestNothingIsAdded` | 모든 발견 원문이 그대로 있음, 합계에 중복 경고, **서술이 비면 결론을 지어내지 않음** |
| `TestNothingIsHidden` | 기각 0건·기각검토 0건이 문장으로 설명됨, 격하 항목이 요약표에 섞이지 않음 |
| `TestDrilldownReachesSource` | 원천 CSV 행의 키와 값이 실제로 렌더링됨, 기본 닫힘 |

결정론적 출력을 테스트로 고정한 이유는 **렌더된 HTML 을 저장소에 커밋해 두기**
때문이다. 실행할 때마다 바이트가 달라지면 diff 가 의미를 잃는다.

## 한계

- 단일 문서다. 발견사항이 수백 건이 되면 목차·검색·페이징이 필요하다.
- 위험등급별 필터가 없다. 자바스크립트를 쓰지 않기로 한 대가다.
- 조서 서식은 이 프로젝트가 정한 것이고, 특정 회계법인의 실제 조서 양식이 아니다.
- 여러 조서를 나란히 비교하는 화면이 없다. 대조군과 LLM 조서를 나란히 놓는 것은
  다음 할 일이다.
